## 1. 시나리오 「숫자가 커진다」

자막 없이 화면만으로 읽혀야 한다. 설명을 버리고 핵심 쾌감 하나만 반복·증폭한다.

**고른다 → 내리꽂는다 → 숫자가 터진다.** 같은 리듬 세 번, 규모만 커진다.

| 구간 | 소스 | 내용 | 체급 |
|---|---|---|---|
| H1 | Higgsfield | 오프닝 — 춘향이 패를 부채처럼 펴들고 정면 응시 | — |

| A2 | 녹화 | 상점 — 특수패 2개 구매 | — |
| H2 | Higgsfield | 브릿지 — 특수패에 불이 붙는 클로즈업 | — |

## 3. 파이프라인

```
node design/14_campaign_video/capture/run.mjs          # 빌드 → 녹화 → 합성
node design/14_campaign_video/capture/assemble.mjs --ratio 4x5   # 편집만
```

| 파일 | 역할 |
|---|---|
| `build-rig.mjs` | 원본 index.html 사본에 리그 주입 (원본 무수정) |
| `rig.js` | 게임 조작 API — 월·목표·손패·조커 지정, 캡처 CSS |
| `scenes.js` | 씬 정의 (A1~A4) + 마크 |
| `vfx.js` | 영상 전용 이펙트 |
| `record.mjs` | Playwright 녹화 (슬로모션 2.5배) |
| `assemble.mjs` | 컷 편집 · 카메라 · 합성 |
| `make-plates.mjs` | CTA 플레이트 (OG 아트) |
| `plates/H1.mp4` 등 | Higgsfield 삽입 — 넣으면 자동 반영 |

### 하드 학습 (다시 밟지 말 것)
- Playwright `recordVideo.size`는 `deviceScaleFactor` 무시 → 뷰포트와 크기를 일치시킬 것
- ffmpeg 표현식에서 `a+(b-a)*e*iw`는 `*iw`가 마지막 항에만 붙음 → **반드시 괄호**
- 강한 감속 이징을 전 컷에 걸면 컷 끝마다 카메라가 멈춰 정지 프레임 발생
- 슬로모션 캡처 시 `setTimeout`만 늦추면 게임 카운트업이 폭주 → `performance.now`·`Date.now`·`rAF` 전부 늦출 것
- `-ss`/`-t`는 **입력 옵션**으로. 출력 옵션이면 setpts 압축분만큼 길이가 어긋남
- SSRock 폰트는 583자 서브셋 — `몇`·`깰`·라틴 문자 없음

## 5. 근본 원인 확정 (2026-08-05)

**뷰포트가 게임 UI보다 훨씬 크다.** 1440×1800으로 녹화하는데 게임 UI는
상단 26%(y 0.01~0.26)만 사용한다 → 하단 74%가 빈 판.

그 빈 공간을 감추려고 카메라를 1.85배 확대해왔고, 그래서
좌측 UI·상단 조커바·상점 모달·팝업이 전부 잘렸다.
**확대는 원인이 아니라 증상이었다.**

### 해결 방향 (다음 작업의 전제)
**뷰포트를 게임 UI가 실제로 쓰는 크기로 줄인다.**
- 1440×1800 → 1440×약 700~760 (게임 콘텐츠 실측 높이)
- 그러면 게임이 뷰포트를 꽉 채우고 **카메라 확대가 0이 된다**
- 4:5 출력은 그 위/아래에 판 배경을 연장하거나, 4:5에 맞는 뷰포트를 직접 산출
- `zoom`으로 레이아웃을 키우는 방식은 실패했다(춘향·좌측 UI와 어긋남) — 쓰지 말 것

## 7. 2026-08-05 2차 수정 (완료)

지적 4건은 전부 **연출의 인과가 끊겨 있던 것**이었다.

| # | 지적 | 무엇을 고쳤나 |
|---|---|---|
| 1 | 점수 팝업이 합산 전에 떠 있다 | 팝업을 `tally`에서 **`sum` 마크(계산·조커 발동이 전부 끝난 뒤)로 이동**. 게임 DOM 폴링을 버리고 씬이 `from`/`gain`을 넘겨 팝업이 스스로 카운트업. `+N`이 수식에서 팝업으로 날아와 꽂힌다(`flyGain`). 좌측 `#side` 전체를 숨김 |
| 2 | 상점 구매에 인과가 없다 | `aim` 컷에서 상품으로 1.0→1.18 줌인 → `flyToJoker()`가 진열 카드를 복제해 **조커바로 퓽 날아가 박힌다** (타격 링·파편·슬롯 발광) → 1.18→1.0으로 빠지며 전 경로를 잡는다 |
| 3 | 엠블럼이 중앙에 안 맞고, 오광이 지어낸 카드 | 엠블럼·팝업 컷을 **배율 1.0 · look 'center'**로 고정(뷰포트 == 프레임). 오광·고도리 엠블럼은 **실제 카드 5장/3장을 레퍼런스로 붙여 GPT Image 재생성** (`make-emblems.sh`) |
| 4 | 오광 후 1고~10고를 빠르게 | `go` 마크 + `goStamp()` — 150ms에서 96ms로 빨라지며 10번 찍힌다. 고/스톱 모달은 `#modal-overlay.gostop-open`만 골라 숨김(상점 모달은 살림) |

같은 패스에서 잡은 영상미 결함:

- **오광 화이트아웃** — `numberBurst`의 섬광을 체급에 비례시켜 알파 0.98·900ms까지 갔다.
  → 세기와 무관하게 **알파 0.55 · 700ms 상한**. 규모는 링·광선·파편으로 낸다
- **엠블럼이 편집에서 통째로 빠짐** — 슬램 컷과 수식 컷 사이 1초에 나타났다 사라졌다.
  → `emblem` 마크를 새로 찍고 **전용 컷**을 줬다
- **글자가 엠블럼을 덮음** — 글자 y 30% / 엠블럼 y 50%로 세로 분리, 글자 크기 상한
  (`160 × min(power, 1.6)` — 오광에서 391px까지 커져 카드를 통째로 가렸다)
- **주막 컷의 흰 프레임** — `fadewhite` 전환이 순백 프레임을 한 장 만들었다(R8) → `fade`

### 하드 학습 추가
- `assemble.mjs`의 `one(rects, 'center')`가 null을 반환해 결국 `focus`로 흘러갔다.
  → **'center'는 명시적으로 CENTER를 돌려줘야** 오버레이 컷이 정중앙에 온다
- `playSelected()`는 `state.roundScore`를 **동기적으로** 더한다.
  "더하기 전 점수"는 `api.play()`가 호출 직전에 찍어둬야 한다
- `codex exec`의 `-i`는 **가변 인자**다. 프롬프트를 뒤에 그냥 붙이면 이미지 목록에 먹혀
  "No prompt provided via stdin"으로 조용히 실패한다 → **`--`로 끊을 것**

### 무대(stage)와 여백 — 구조 변경

```
녹화 뷰포트 1080×1350  ← 최종 프레임과 같은 크기
  └ 무대 860×1075      ← 게임은 여기에만 그린다 (rig.js --cap-stage)
     둘레 110px / 137px = 카메라 예비 공간 (게임 배경이 채운다)
```

- `record.mjs` VIEW = 1080×1350, `rig.js` `--cap-stage: 860px / --cap-stage-h: 1075px`
- `assemble.mjs` 기본 배율 `Z = 1080/860 ≈ 1.256` — 무대를 프레임에 꽉 채운다
- 이제 **확대하거나 팬해도 바깥에 진짜 화면이 있어 잘리지 않는다.**
  세 값(VIEW / --cap-stage / STAGE_W)은 **반드시 같이 고쳐야 한다**
- VFX 크기도 뷰포트가 아니라 무대 기준(`calc(var(--cap-stage) * .68)` 등).
  `vw`로 두면 여백까지 계산해 이펙트가 프레임보다 커진다
- 상점 모달은 `max-width:860`이라 무대 폭과 같아 가장자리가 프레임에 딱 붙었다
  → `#modal { max-width: calc(var(--cap-stage) - 96px) }`

### 하드 학습 추가
- `body { will-change: transform }`은 **fixed 자손의 컨테이닝 블록을 body로 만든다.**
  `#modal-overlay`가 뷰포트가 아니라 body 박스 기준이 돼 어긋났다 → 프레이밍 모드에서만 쓸 것
- 요소가 왜 안 채워지는지 모르겠으면 추측하지 말고 **Playwright로 실측**할 것.
  `padding-right:200px` 한 줄을 찾는 데 그게 제일 빨랐다

### 카메라 주시점 보간 버그 (전 컷에 영향)
주시점을 '크롭 창 좌상단 비율'로 **미리 환산해 두고 그 값을 이었다.**
이 환산 `(c - 1/2z) / (1 - 1/z)`는 배율에 따라 분모가 달라지는 **비선형** 변환이라,
배율이 변하는 컷에서는 같은 중심(0.5)이 배율마다 다른 비율이 된다
(z=2.35에서 0.5, z=1에서 0) → 그 사이를 직선 보간하니 화면이 옆으로 휘며 흘렀다.

→ **중심 좌표를 그대로 보간하고 크롭 좌상단은 매 프레임 계산한다.**
```
x = max(0, min(iw-iw/zoom, iw*cx - iw/zoom/2))
```
로고뿐 아니라 배율이 변하는 모든 컷의 미세한 좌우 흐름이 같이 사라졌다.

### 새 도구

  `use`를 손으로 적으면 씬 타이밍이 조금만 바뀌어도 겹치거나 구멍이 난다

## 16. 2026-08-06 11차 — 수식이 안 보이던 이유

**증상**: 「칩 × 배수 = 점수」 수식이 화면에 거의 안 뜨고, 뜨더라도 다 끝난 뒤에
잠깐 스치듯 지나갔다.

**원인**: 집계 게이트를 풀어도 수식이 **바로 뜨지 않는다.**
게임은 release 뒤에 이 순서를 밟는다.

```
release → 배너 대기 340ms(큰 족보는 480ms) → 배너 정리 160ms
        → 수식 opacity 0 → 1 페이드 280ms
```

즉 **release + 약 0.8초**에야 보이기 시작한다.
그런데 씬은 release 직후 180ms에 `mark('tally')`를 찍고 있었고,
그 마크 기준 1.1초짜리 컷은 **전 구간이 opacity 0인 빈 화면**이었다.

**수정**
- `releaseTally()` 뒤 대기 180 → **860ms**. 수식이 실제로 보이는 시점에 마크를 찍는다
- 수식 컷 길이를 `to: ['sum'|'joker', …]`로 바꿔 **칩이 다 올라갈 때까지** 유지
- 칩 색이 인게임 기본(`--chip-blue`)이라 판 위에서 가라앉았다 → 밝은 하늘색 + 발광
- 카드와 수식 사이 간격 22px로 벌려 수식이 카드에 붙어 읽히게

결과: `10 → 20 → 30 → 30 × 6 → 30 × 6 = 136 → 180`이 낸 패 바로 아래에서
챡챡챡 올라간다.
