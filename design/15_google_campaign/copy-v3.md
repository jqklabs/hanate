## 0. v3에서 바뀐 작성 규칙

타 캠페인 실측 데이터([images-v3.md §2.5](images-v3.md))에서 텍스트 채널의 승패가 명확히 갈렸다.

| | 승자 | 패자 |
|---|---|---|
| 형식 | **2인칭 + 메커니즘 직격** (`Your Dice, Your Build`) | 세계관 서사 |
| 형식 | **카테고리 정의문** (`A dice deckbuilder meets…`) | 분위기·감성 문구 |

**따라서 v3 문구는 세 가지 형태만 쓴다.**

1. **2인칭 소유형** — "당신의 ○○가 곧 당신의 ○○" 구조. 플레이어를 주어로 세운다
2. **카테고리 정의문** — "화투 48장 덱빌딩 로그라이크". 무슨 게임인지 3초에 답한다
3. **숫자 증명형** — 160/5,500, 13종/22종, 승률 0%. 검증 가능한 실측치만

**금지** — 춘향 서사, 조선 세계관, 계절 감성, 시적 표현. 이미지 컨셉의 「열두 달 화첩」은 시각 축이지 **문구 축이 아니다**. (v3 이미지 기획서 §3의 월별 멘트는 전부 세계관 서사형이라 **광고 문구로 승격하지 않는다** — 이미지 조판용으로만 남긴다.)

**정책** ([README §4](README.md)) — 내기·베팅·도박·판돈·잭팟·당첨 전면 금지, "발라트로" 금지, 카테고리 단어는 항상 로그라이크/덱빌딩.
**고스톱 회피** — 고스톱·고도리·초단·청단·박·냥을 문구에서 쓰지 않는다. **"화투"는 쓴다** — 차별화 축이므로 지우면 안 된다.

## 3. 설명 (한도 90 / 한글 45자)

제목이 후킹을 맡으면 설명은 **"그래서 뭘 하는 게임인가"에 답하는 자리**다.
5개를 세 형태에 배분하되, 제목보다 한 단계 구체적으로 쓴다 — 제목이 `당신의 패, 당신의 빌드`라면 설명은 그 인과를 문장으로 완성한다.

| # | 문구 | 소모 | 형태 | 노리는 것 |
|---|---|---|---|---|
| 1 | **화투 48장으로 덱을 짜는 로그라이크. 손패 8장에서 골라 점수를 만든다.** | 68/90 | 카테고리 정의 + 룰 | 기본값. 카테고리와 실제 조작(8장 중 고른다)을 한 줄에 넣어 3초 안에 "무슨 게임인지"를 끝낸다 |
| 2 | **당신이 고른 패가 빌드가 되고, 빌드가 점수를 터뜨린다.** | 53/90 | 2인칭 소유 | 짧은제목 #1의 인과 완결. 선택 → 빌드 → 점수의 루프를 한 문장으로 |
| 3 | **족보 13종, 특수패 22종. 1월 160점에서 12월 5,500점까지.** | 55/90 | 숫자 증명 | 볼륨(13·22)과 커브(34배)를 한 줄에. 숫자만으로 깊이를 증명 |
| 4 | **아는 그림이 그대로 점수가 된다. 새로 배울 룰이 없는 덱빌더.** | 59/90 | 2인칭 + 마찰 제거 | 화투 아는 층의 진입장벽 제거. "족보" 대신 "아는 그림"으로 고스톱 신호를 뺐다 |
| 5 | **그리디 AI 봇 승률 0%. 당신은 몇 월까지 갈 수 있나?** | 50/90 | 숫자 증명(도발) | **반드시 넣을 것.** 실측 근거 + 2인칭 도발. 한정어 "그리디 AI 봇"을 절대 떼지 말 것 |

예비(교체용): `설치도 로그인도 없다. 브라우저에서 바로 시작하는 무료 덱빌더.` (61/90)

**짧은 설명 (Demand Gen 60 / 한글 30자)** — `패를 골라 점수를 터뜨리는 화투 덱빌딩 로그라이크.` (49/60)

> 톤은 v3 제목과 맞춘 **평서 단정형(`~된다`)**. v1 설명의 존댓말(`~하세요`)과 섞으면 조합 시 문체가 튄다 — v3 세트는 세트째로 쓴다.

## 4. 조합 규칙 — 겹치는 짝

구글이 제목·설명을 자동 조합하므로 **같은 말이 두 번 나오는 짝**만 광고그룹으로 갈라 회피한다. 나머지는 전부 독립 문장이라 어떻게 붙어도 말이 된다.

| 겹치는 짝 | 중복 |
|---|---|
| 짧은 #2 `화투 48장 덱빌딩 로그라이크` + 설명 #1 | 카테고리 정의 2회 |
| 짧은 #4 `AI 봇도 못 깬` + 설명 #5 `AI 봇 승률 0%` | 도발 2회 |
| 짧은 #5 `족보 13 · 특수패 22` + 설명 #3 | 숫자 2회 |
| 짧은 #1 `당신의 패, 당신의 빌드` + 긴 #2 + 설명 #2 | 셋 다 같은 인과 — **둘까지만** |

**권장 광고그룹 2개** (v3는 A/B 오디언스 분리를 하지 않는다 — 형태로 나눈다)

| 그룹 | 짧은제목 | 긴제목 | 설명 |
|---|---|---|---|
| **정의·마찰** (신규 유입) | 2, 3, 5 | 1, 4 | 1, 3, 4 |
| **소유·도발** (하드코어) | 1, 4 | 2, 3, 5 | 2, 5 |

## 5. 이미지 슬롯 ↔ 문구 매핑

Demand Gen은 이미지와 텍스트를 조합해 게재하므로, **이미지가 답하지 못하는 것을 문구가 답해야** 한다. v3 이미지는 카테고리를 말하지 않으므로(글자를 넣지 않는다) 카테고리 단어는 전적으로 문구가 책임진다.

| 이미지 성격 | 붙일 문구 | 이유 |
|---|---|---|
| 카드가 가장 큰 장 (가로형) | 짧은 #1 · 긴 #2 | 시각이 이미 "패"를 말하므로 문구가 "빌드"를 이어받는다 |
| 계절색이 강한 장 | 짧은 #2 · 긴 #1 | 이미지가 예쁘기만 할 때 카테고리를 문구가 못 박는다 |
| 어둡고 무거운 장 (박 라운드 달) | 짧은 #4 · 긴 #5 | 난이도 도발과 톤이 맞는다 |
| 밝은 장 (입구 묶음) | 짧은 #5 · 긴 #4 | 진입 장벽 낮추기 |

## 6. ⚠️ 검증

문구를 고치면 **반드시** 자수를 다시 잰다. 초과분은 등록 단계에서 잘려 문장이 깨진다.

```bash
node src/charcount.mjs   # v1 + v3 세트 전부
```

v3 세트(짧은제목·긴제목·설명·짧은설명)는 `SETS` 배열에 블록으로 들어가 있다. **전부 통과 확인됨.**

> 금지어 검사는 v1·v3 공통 목록(`내기/베팅/도박/판돈/잭팟/당첨/발라트로`)만 자동화돼 있다.
> v3의 추가 회피어(고스톱·고도리·초단·청단·박·냥)는 v1 세트가 실제로 쓰고 있어 자동 검사에 넣지 않았다 — **v3 문구는 눈으로 확인할 것.**
