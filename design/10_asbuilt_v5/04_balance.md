## 2. 파생 수식

### 점수

```
cardChip(c) = base(c.type)
              × 2                     if c.month == 현재 월        (이달의 패)
              + 2                     if 낮 && type ∈ {광, 열끗}
              + 2                     if 밤 && type ∈ {띠, 쌍피, 피}
              = 0                     if 박 대상 && !피박보험      (덮어쓰기)

chips = Σ cardChip(c)   for c ∈ core
flat  = Σ cardChip(c)   for c ∉ core   +  Σ addChips(joker)

mult  = HANDS[handId].mult
        + Σ addMult(joker)             (가산 먼저)
        × Π xMult(joker)               (승산 나중)

score = floor(chips × mult + flat)     ← floor는 여기 1회만 (POL-SCR-03)
```

- `base`: 광 12 · 열끗 8 · 띠 6 · 쌍피 5 · 피 2
- 밤낮 판정: `isNight() = round % 2 === 0` → **홀수 달 낮 ☀️ / 짝수 달 밤 🌙**
- 쌍피는 족보 판정에서 피 2장으로 환산(`piCount`)되지만 **칩은 5** (피 2장 = 4보다 크다)

### 목표 커브

실측 `TARGETS = [160, 240, 330, 450, 600, 820, 1150, 1600, 2200, 3000, 4100, 5500]`은 **기하수열에 손으로 맞춘 값**이다. 역산:

```
r = (T₁₂ / T₁)^(1/11) = (5500 / 160)^(1/11) = 34.375^0.0909 = 1.3793
T(n) ≈ 160 × 1.3793^(n−1)
```

### 고 문턱

```
goThreshold(base, n) = ceil(base × (1 + 0.6n))
goLevelReached(base, score, cur) = max n such that score ≥ goThreshold(base, n)   (cur 미만 불가)
선언 시:  goLevel ← goLevelReached(base, score, goLevel) + 1
          target  ← goThreshold(base, goLevel)
          playsLeft += 1                                  (선언 1회당 1, 밀친 단계 무관)
goBonus(n, m) = n × m                                     (m = 현재 월)
```

**밀치기 불변식**: 선언 단계는 정의상 "아직 못 넘은 첫 문턱"이므로 `target > score`가 항상 성립한다 → 공짜 연쇄 고가 수학적으로 불가능. (엔진 테스트 `[4]`가 5개 케이스로 검증)

### 정산

```

base      = isBossRound(round) ? 6 : 4
playBonus = playsLeft                        (남은 내기 1회당 1냥)

insBonus  = 피박보험 보유 ? 1 : 0
total     = interest + base + playBonus + goB + insBonus
```

## 3. 진행 밴드 R(n) — 이 게임의 핵심 지표

`R(n) = P(n) / D(n)` = (무조커 손패 8장 최적 4회 합) / (목표). 목표 밴드 `0.90 ≤ R ≤ 1.15`.

> 손패 8장 무작위 100회 × 12개월, 각 손패의 1~5장 전 부분집합 최적값. 특수패·고 없음.

| 5 | 600 | 73 | 292 | **0.49** | 🔴 |
| 6 | 820 | 71 | 285 | **0.35** | 🔴 |
| 7 | 1,150 | 78 | 313 | **0.27** | 🔴 |

**이것이 이 게임의 밸런스 정체성이다.**

- 무조커 소재 파워 `P(n)`은 **월과 무관하게 285~313으로 평평하다.** 카드 칩·족보 배수가 고정이고, 이달의 패(×2)와 밤낮(+2)이 서로 상쇄되기 때문.
- 반면 `D(n)`은 매달 ×1.379로 오른다.
- 따라서 **R은 3월에 밴드를 뚫고 내려가 이후 지수적으로 붕괴**한다.
- 그 간극 전부를 메우는 것이 **특수패 배수 + 고 스노우볼**이다. 12월 기준 필요 배수는 `1/0.06 ≈ 16배`.

**설계 검증**: R이 처음 0.9 아래로 내려가는 지점이 정확히 **3월**이고, 실측 무조커 3월 통과율이 **14%**다 (앵커 A8 = ~15%). ✅ **모델과 실측이 일치한다.**

## 5. 특수패 가격 검산

```
가격 = base × 희소도계수
```

| 티어 | 종수 | 출현 | 가격 실측 | 평균 | 평균/커먼 | 출현 역수비 |
|---|---|---|---|---|---|---|
| 커먼 | 6 | 55% | 3/4/4/4/4/4 | 3.8 | 1.00 | 1.00 |
| 레어 | 7 | 28% | 6/6/6/6/6/7/7 | 6.3 | 1.66 | 1.96 |
| 에픽 | 6 | 13% | 9/9/9/10/10/10 | 9.5 | 2.50 | 4.23 |
| 레전더리 | 3 | 4% | 13/14/15 | 14.0 | 3.68 | 13.75 |

**판정**: 가격이 출현 역수보다 **완만하다** (레전 13.75배 희귀한데 3.68배 가격). 레전더리가 **가격 대비 압도적으로 유리**하며, 이것이 "종반은 에픽/레전 빌드가 필수"라는 설계와 일치한다. ✅ 의도적.

⚠️ 단, 시나리오 C 기준 9월 보유 109냥이면 **레전더리도 즉시 살 수 있다**. 가격이 병목이 아니라 **출현 확률(4%)만이 병목**이다 → 실질적으로 상점은 "돈을 쓰는 곳"이 아니라 "리롤 운을 사는 곳".

### 티어 출현 확률 검산

```
누적 임계값: r < 0.55 → common, < 0.83 → rare, < 0.96 → epic, else legendary
⇒ 55% / 28% / 13% / 4%   (합 100%) ✅
```

⚠️ **`RARITY_WEIGHT` 상수는 선언만 되어 있고 사용되지 않는다** — 실제 추첨은 하드코딩 임계값. 이중 정의 (`03_data §1`).

**슬롯 3개 중 레전더리 1장 이상 등장 확률**: `1 − 0.96³ = 11.5%`
**11회 상점 동안 레전더리를 한 번도 못 볼 확률**: `0.96³³ = 25.9%` — **4명 중 1명은 런 내내 레전더리를 못 본다.**

`[확인필요]` 종반이 레전더리 의존적인데 26%가 못 본다 → 천장(pity) 개념 부재. 리롤로 보완 가능하나 명시적 보장은 없다.

> ⚠️ **위 두 확률은 "초기 8장" 기준이며, 회전을 고려하면 성립하지 않는다.** 광을 쥐고 나머지를 8액션 회전시키면 덱 40.8/48장을 열람하게 되고, **광 3장 이상 99.4% · 오광 47.8%** 로 뒤집힌다(110배). 실측·대책: `../12_gwang_exploit/`. §6 수치 정정은 해당 기획의 승인 항목 #5 대기 중.

| 최약 (무조커, 최적 손패) | 88 (평균) / 864 (덱 전체 최적=오광) | 5,500 | 🔴 불가 |

| 최강 (엔드게임 빌드, 오광) | **8,690** | 5,500 | ✅ 1.58배 여유 |

**엔드게임 빌드 정의**: 명인(×2) + 오광소원(×2.5) + 비광우산(×2) + 광모이(+50 flat) + 삼광판(오광엔 미적용)

### 7-2. 손 검산 — 12월 오광 (스크립트와 대조)

```
손계산:
  12월 = 짝수 달 = 밤 → 띠·피 +2 (광엔 무영향)
  광 5장 중 12월 비광만 이달의 패 → 12 × 2 = 24
  나머지 광 4장 → 12 each = 48
  chips = 48 + 24 = 72
  mult  = 12 (오광) × 2 (명인) × 2.5 (오광소원) × 2 (비광우산: core에 12월 有) = 120
  flat  = 광모이 10 × 5 = 50
  score = floor(72 × 120 + 50) = 8,690
```

```
엔진 실행 결과: {"handId":"ogwang","chips":72,"mult":120,"flat":50,"score":8690,"kwangPlayed":5}
```

✅ **완전 일치.** 칩 보정 순서·배수 결합 순서·floor 1회 규칙이 전부 설계대로 동작한다.

### 7-3. 손 검산 — 3월 벽 (대표 중반 시점)

```
3월 = 홀수 달 = 낮 → 광·열끗 +2 / 이달의 패 = 3月 카드 ×2
무조커 손패 평균 최적 1회 = 72점 → 4회 = 289점
목표 330점 → R = 0.88
필요 추가 = 41점 = 커먼 특수패 1장(피장사 4×5=20 / 광모이 10×2=20)으로 겨우 도달
```
✅ **"1월 상점에서 커먼 1장을 사면 3월을 넘길 확률이 생긴다"** — 시작 자금 4냥(A6)의 설계 근거가 검증된다.

### 7-4. 손 검산 — 1월 (초반 시점)

```
목표 160, 무조커 4회 합 270 → R = 1.69
1회 평균 67점이면 3회로 201점 → 남은 내기 1회는 정산 보너스 1냥
```
✅ 튜토리얼 통과 실측 **100%** (앵커 A3 충족).

### 7-5. 민감도 — 고 계수 `k` ±20%

> `goThreshold(base,n) = ceil(base × (1 + k·n))`

| 계수 k | 1고(1월) | 2고 | 3고 | 5고 | 12월 1고 | 12월 3고 | 결과 변화율 |
|---|---|---|---|---|---|---|---|
| 0.48 (−20%) | 237 | 314 | 391 | 544 | 8,140 | 13,420 | −7.5% (1고) |
| **0.60 (현행)** | **256** | **352** | **448** | **640** | **8,800** | **15,400** | — |
| 0.72 (+20%) | 276 | 391 | 506 | 736 | 9,460 | 17,380 | +7.5% (1고) |

✅ **안전.** 파라미터 변화율 20% → 결과 변화율 7.5%. 지배적이지 않다. 미세 조정 레버로 적합하며, `HANDOFF.md`가 "인플레/디플레 재발 시 문턱 계수(0.6)만 미세 조정"이라 한 것과 정합.

단 고 단계 n이 커질수록 민감도가 커진다(3고에서 ±13%). **고를 많이 미는 후반 빌드에 더 크게 작용**한다.

### 7-6. 민감도 — 목표 커브 배율 `r` ±20%

> `T(n) = 160 × r^(n−1)`

| r | T(3) | T(6) | T(9) | T(12) | 현행 대비 |
|---|---|---|---|---|---|
| 1.103 (−20%) | 195 | 261 | 351 | 470 | **−91%** ⚠️ |
| **1.379 (현행)** | **304** | **798** | **2,092** | **5,487** | — |
| 1.655 (+20%) | 438 | 1,987 | 9,005 | 40,822 | **+642%** ⚠️ |

🔴 **`r`은 결과를 지배하는 파라미터다** (변화율 50% 초과). 지수의 밑이라 12제곱으로 증폭된다.

**대응**: `r`은 절대 감으로 만지지 않는다. 조정이 필요하면
1. `r`이 아니라 **개별 월의 목표값**을 손보거나,
2. `r`을 만졌으면 **반드시 봇 600런 재실행**으로 A7·A8을 재확인한다.

→ `balance_params`의 `curve_r`에 `min/max` 가드를 걸 대상 (§8).
