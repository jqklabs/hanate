## 1. 활성화 정의

이 게임에는 가입이 없다. 첫 세션 = 온보딩 전부다.

| 단계 | 이벤트 | 의미 |
|---|---|---|
| 도달 | `session_start` | 랜딩 |
| **첫 값** | **첫 `hand_play`** | 패를 한 번 냈다 = 게임을 만졌다 |
| **활성화** | **1월 클리어 (`settle` 1회)** | 루프 한 바퀴를 돌았다 |
| 습관 | 유저당 런 ≥ 3 (수익화 §6) | 로그라이크가 성립했다 |

**아하 모먼트는 "첫 점수 폭발"이 아니라 "1월 클리어"다.** 점수가 터지는 건 연출이고, 정산 → 상점 → 다음 달로 이어지는 순간에야 이게 한 판짜리 퍼즐이 아니라 **런**이라는 게 전달된다. 상점 코치(`shop`)가 그 자리에 이미 놓여 있는 건 정확한 판단이다.

> `hand_play`를 광고 입찰 최적화 기준으로 쓰기로 한 것([캠페인 README §5](../design/15_google_campaign/README.md))과 일치한다. 다만 **입찰 기준(첫 값)과 활성화(1월 클리어)를 같은 것으로 착각하지 말 것.**

## 2. 현재 첫 세션 플로우 (코드 기준)

```
boot()                              index.html:5276
  └ 에셋 프리로드 (최소 550ms 대기)
  └ hasSeenHowto() ? 'prep' : 'welcome'          :5305

welcome  ─ 규칙 카드 4장 전문 ─ [알겠어요 — 시작하기]   welcomeHTML :6142
prep     ─ 1월 목표 + 춘향 예약 ─ [▶ 1월 시작]          prepHTML    :6188
play     ─ coach: hand → play → scored → junk → deck   renderCoach :5979
           1월 오라 무료 3회 (JAN_AURA_USES)             :3469
gostop / shop 코치는 해당 화면 첫 진입 시 1회
```

**첫 `hand_play`까지: 클릭 관문 2회 + 규칙 텍스트 약 400자.**
관문 수 자체는 문제가 아니다. 문제는 그 400자가 **뒤에 오는 코치와 같은 내용**이라는 것이다.

## 3. 발견 사항

### 🔴 F1 · 온보딩 퍼널이 전혀 계측되지 않는다 — P0

**발견**: `trackEvent` 호출 8곳(`index.html:4034, 4275, 4317, 4372, 4413, 4566, 4570, 4577, 5364`) 중 **온보딩 이벤트는 0개**. 웰컴 표시/닫기, 코치 스텝 진행/건너뛰기, 오라 사용이 아무것도 기록되지 않는다.

**영향**: `session_start` → 첫 `hand_play` 전환율은 계산되지만, **어디서 빠졌는지는 알 수 없다.** 웰컴 모달에서 닫았는지, prep에서 나갔는지, 손패를 보고 얼렸는지 구분이 불가능하다. 지금 상태에서 온보딩을 고치면 **좋아졌는지 나빠졌는지 판정할 수단이 없다.** 재미 설문([13_fun_survey](../design/13_fun_survey/plan.md))도 아직 미실행이라 정성 데이터도 없다.

**권고** — 이벤트 3개만 추가한다(기존 `trackEvent` 스키마 그대로).

| 이벤트 | 파라미터 | 붙일 위치 |
|---|---|---|
| `onboard_welcome` | `action`(shown\|dismissed) | `boot()` :5305 · `dismissWelcome()` :5090 |
| `coach_step` | `step`(hand\|play\|scored\|junk\|deck\|gostop\|shop), `action`(shown\|next\|skip), `month` | `renderCoach()` :5979 · `coachNext()` :5041 · `coachSkip()` :5065 |
| `jan_aura_use` | `uses_left`, `hand_id` | 오라 소모 지점 :3944 |

읽을 것: **스텝별 이탈률**과 **건너뛰기율**. 건너뛰기율이 높은 스텝은 "불필요"가 아니라 대개 "너무 길다"는 신호다.

**이걸 먼저 붙이지 않고 F2·F3을 고치는 건 눈 감고 수술하는 것이다. 순서를 지킬 것.**

### 🔴 F2 · 웰컴 모달이 "보여주기 전에 가르친다" — P0

**발견** (`welcomeHTML` :6142): 첫 화면에서 카드 4장으로 **기본 플레이 + 점수 공식 + 이달의 패 ×2 + 밤낮 +2 + 고/스톱 + 밀치기 + 고박 + 박 라운드 + 상점 22종**을 전부 설명한다. 유저는 아직 화투패를 한 장도 보지 못한 상태다.

**영향**: 이 게임의 진입장벽은 화투가 아니라 **스코어링 규칙**이다(설문 설계 D4가 정확히 이걸 묻는다). 텍스트로 미리 읽은 규칙은 거의 남지 않는다 — 그리고 **바로 뒤에 같은 내용을 손잡고 가르치는 코치가 이미 있다.** `scored` 스텝(:6031)은 실제 자기 점수로 `(칩 × 배수) + 나머지`를 보여주는데, 이게 웰컴 카드의 설명보다 압도적으로 잘 가르친다.

특히 **고/스톱과 박은 웰컴에 있을 이유가 전혀 없다.** 고/스톱은 첫 목표 달성 시 `gostop` 코치가, 박은 3월에 처음 만난다. 최소 10분 뒤에 쓸 정보를 0분에 준다.

**권고** — 웰컴을 **3줄 + 시작 버튼**으로 줄인다. 나머지는 이미 있는 코치와 📖 도움말에 위임.

```
        🎴 화투로 — 고스톱: 무한의 판

  화투 48장으로 족보를 맞춰 목표 점수를 넘기는 1인 런입니다.
  손패 8장에서 1~5장을 골라 내면 점수가 됩니다.
  1월부터 12월까지, 한 해를 버텨보세요.

        [ ▶ 1월 시작하기 ]

     규칙은 하면서 알려드릴게요 · 족보표는 📖에 있습니다
```

- 점수 공식·밤낮·고/스톱·박·상점 카드 **4장 전부 삭제** → 도움말(`helpHTML` :6437)에 이미 전부 있다
- 마지막 한 줄이 **"안 읽어도 된다"는 허락**이다. 규칙 게임에서 이 허락이 첫 이탈을 가장 크게 줄인다
- **prep 화면을 웰컴에 합친다** — 첫 런에 한해 `dismissWelcome()`이 `prep`이 아니라 곧장 `beginFromPrep()`으로 가면 관문이 2 → 1로 준다. (재방문자는 기존대로 prep 유지 — 춘향 예약이 필요하다)

> ⚠️ **반드시 A/B로 검증할 것.** 규칙이 복잡한 게임에서 설명을 줄이는 건 정답이 아닐 수 있고, 특히 화투를 모르는 층에서 역효과가 날 수 있다. F1 계측 후 2주.

### 🟠 F3 · 3월 박 라운드에 보조가 0이다 — P1

**발견** (`renderCoach` :5985–5989): 코치 표시 조건이 `state.screen === 'play' && state.round === 1`. **1월에서만 뜬다.**

**영향**: 그리디 봇 300런 중 약 86%가 3월에서 죽는다(README 밸런스). 3월은 **첫 박 라운드**이자 실측된 최대 이탈 지점이고, 박은 이 게임에만 있는 개념이다(피박/광박/멍박/흔들기 금지/비바람/안개). 상점에서 예고는 뜨지만 **"그래서 뭘 다르게 해야 하는가"를 알려주는 것이 아무것도 없다.** 웰컴에서 읽은 한 줄("3·6·9·12월은 박 라운드")은 이미 20분 전에 증발했다.

**권고** — `bak` 코치 스텝 1개 추가. 3월 첫 진입 시 1회, 평생 1회.

```
🌧️ 박 라운드
이번 달은 [광박]. 광 카드의 칩이 0이 됩니다.
평소 쓰던 빌드가 안 통해요 — 다른 족보를 노려보세요.
                                        [ 알겠어요 ]
```

- 걸린 박에 따라 body만 분기(6종). 조건은 `state.round === 3 && 첫 진입`
- 상태 키는 기존 패턴 그대로 `hwatro_bak_coach_v1`
- **이 하나가 이 문서에서 리텐션 기대효과가 가장 큰 항목이다.** 최대 이탈 지점에 처음으로 보조를 놓는 것이기 때문

### 🟠 F4 · 1월 오라가 절벽으로 끝난다 — P1

**발견** (`JAN_AURA_USES = 3` :3469): 1월에 조합 자동 선택 3회 무료. 이후에는 힌트 토글(`hintEnabled`)로 넘어간다.

**영향**: 족보는 13종이다. 3회로는 못 익힌다. 4회째부터 유저는 갑자기 혼자가 되는데, **힌트를 계속 켤 수 있다는 사실을 알려주는 스텝이 없다.** 오라가 꺼진 걸 "튜토리얼이 끝났다"가 아니라 "기능이 사라졌다"로 읽으면 그대로 이탈한다.

**권고** — 3회를 다 쓴 직후 한 줄 토스트. 새 시스템 없이 안내만.

```
✨ 무료 추천을 다 썼어요. 추천은 [힌트] 버튼으로 언제든 켤 수 있습니다.
```

**대안(더 나음, 공수 큼)** — 2월에 오라 1회를 남긴다. 절벽 대신 페이드. 다만 밸런스 문서상 2월은 이미 난이도 여유 구간이라 실익이 크지 않을 수 있어 **토스트 먼저**를 권한다.

### 🟡 F5 · 코치 상태 키가 흩어져 있다 — P2

**발견**: `hwatro_jan_coach_v1` / `_shop_` / `_gostop_` / `_deck_` (:4746–4790) + `hwatro_howto`. 코치를 하나 추가할 때마다 키가 하나 늘고, `replayTutorials()` (:4794)가 전부를 알아야 한다.

**영향**: 지금은 동작한다. F3의 `bak`을 넣으면 5번째 키다. 튜토리얼 버전을 올릴 때(v2) 전 키를 손으로 갱신해야 한다.

**권고**: `hwatro_coach = {jan:1, shop:1, gostop:1, deck:1, bak:1, v:1}` 단일 객체로 통합. F3 구현할 때 같이 하면 추가 공수가 거의 없다. 기존 키 → 신규 객체 1회 마이그레이션.

### 🟡 F6 · 오랜만에 돌아온 유저에게 재학습이 없다 — P2

**발견**: `hasSeenHowto()`가 true면 영구히 웰컴을 건너뛴다(:5305).

**영향**: 규칙 밀도가 높은 게임인데 30일 만에 돌아온 유저도 아무 안내 없이 prep으로 떨어진다. 다만 재방문자 자체가 적은 현 단계에서 우선순위는 낮다.

**권고**: `session_start`의 `days_since_last`가 이미 수집된다(analytics.md). **30일 이상이면 웰컴을 1회 다시 띄운다.** 조건 한 줄이면 끝난다.

### 🟡 F7 · 모바일 코치 패널 위치 — P2 (확인 필요)

**발견** (`renderCoach` :6074): `panelLeft = Math.min(Math.max(12, x), window.innerWidth - 360)` — 패널 폭 360px을 가정한다. 뷰포트가 372px 미만이면 `innerWidth - 360`이 12보다 작아져 항상 좌측 12px에 고정되고, 하이라이트 대상과 패널이 어긋날 수 있다.

**권고**: 실기기(iPhone SE 375px, 갤럭시 폴드 커버 344px)에서 1월 코치 5스텝을 육안 확인. **코드보다 확인이 먼저** — 실제로 깨지는지 보고 판단한다.

## 5. 만들지 않기로 한 것 (표준 온보딩 패턴 중)

| 패턴 | 기각 이유 |
|---|---|
| **온보딩 체크리스트 / 진행바** | 1월 → 12월이 이미 진행바다. 게임 위에 별도 진행 UI를 얹으면 몰입을 깨고 화면만 좁힌다 |
| **가이드 투어(전 UI 순회)** | 이미 있는 코치가 상황 기반(context-triggered)이라 더 우월하다. 순회 투어는 "Do, don't show" 위반 |
| **샘플/데모 데이터** | 게임에는 빈 상태가 없다. 첫 손패 8장이 곧 실데이터 |
| **온보딩 이메일 시퀀스** | 계정도 이메일도 없다. 그리고 만들지 않기로 했다([수익화 §2-D](수익화-방안.md)) |
| **이탈 유저 재참여 푸시** | 동상. 채널이 없다 |

## 6. 측정 계획

F1 이후 2주간 볼 것.

| 지표 | 산출 | 목표(제안) |
|---|---|---|
| 첫 값 도달률 | 첫 `hand_play` / `session_start` | ≥ 70% |
| **활성화율** | 1월 `settle` / `session_start` | **≥ 45%** |
| 웰컴 통과율 | `onboard_welcome:dismissed` / `:shown` | ≥ 85% |
| 코치 완주율 | `coach_step:next` / `:shown` (스텝별) | 스텝별 이탈 20% 미만 |
| 3월 도달률 | `run_end.month >= 3` / 런 | 봇 14% 대비 **유의미하게 높아야** 한다 |
| 첫 값까지 시간 | `session_start` → 첫 `hand_play` | 90초 이내 |

> 목표치는 전부 **제안치**다. 이 게임의 벤치마크가 없으므로 2주 실측 후 재조정한다. 첫 2주의 값은 "목표 달성 여부"가 아니라 **기준선**으로 쓴다.

## 7. 실험 순서

트래픽이 얇다. 동시에 하나, 최소 2주 또는 세션 500 중 늦은 쪽.
