# AI 슬롭 진단 — 십이화 UI

`kill-ai-slop` 스킬(`yetone/kill-ai-slop`)로 스캔 후 전 항목을 직접 읽고 판정한 결과.
**진단만 정리한 문서 — 코드는 아직 고치지 않았다.**

- 스캔 범위: 전체 75파일 → 14그룹 732건
- 제품면(`index.html` · `pages/guide/` · `README.md`, `design/`·`docs/` 제외): 14그룹 314건
- 직접 확인 후 **진짜 슬롭 9그룹**. 나머지는 오탐이거나 의도된 연출.
- 대상 커밋: `e4f4148` (가이드 페이지 추가 이후) 기준 줄번호.

제품면은 둘이다 — **게임 본편**(`index.html`)과 **게임 가이드**(`pages/guide/index.html`, AdSense 심사용).
성격이 달라 나눠서 정리한다.

---

## 한 줄 진단

**카드 48장은 그려진 그림인데, 그 위의 UI는 전부 이모지와 Tailwind 기본색이다.**

`Assets/`에 월별 화투 아트 54장(webp)이 실려 있고 실제로 렌더된다([`index.html:4552~`](../index.html#L4552), [`8592`](../index.html#L8592)).
그런데 그 카드를 감싸는 모든 레이어 — 족보표 그림, 특수패 아이콘, 춘향 얼굴, 월 표시, 버튼 라벨 —
는 이모지로 채워져 있다. 아트 디렉션이 한 화면 안에서 두 갈래로 갈린다.

색도 같은 문제다. `:root` 토큰이 11개(`--felt`/`--gold`/`--frame`…)뿐이라
중립색·등급색·상태색이 비어 있고, 그 빈자리를 Tailwind 기본 팔레트 하드코딩 **171회**가 메우고 있다.

가이드 페이지는 별개의 문제를 갖고 있다 — **본편과 폰트·색·모양을 하나도 공유하지 않는다.**
Georgia 세리프 + 라운드 24px + 3열 카드 그리드 + `01 · / 02 ·` 번호 키커로,
게임 화면이 아니라 SaaS 랜딩 템플릿에 가깝다.

# A. 게임 본편 (`index.html`)

## 1. 이모지가 아이콘 체계를 대신한다 — 205회, 고유 72종

가장 큰 문제. 이모지는 OS마다 다르게 그려지므로 **아트 디렉션을 OS에 외주 준 것과 같다**.
카드에는 직접 그린 아트를 쓰면서 그 위 UI는 애플/구글이 그린 그림으로 채워져,
같은 화면에서 두 화풍이 부딪힌다.

| 위치 | 현재 | 문제 |
|------|------|------|
| `9489` `HAND_VIS` | 족보표 15행이 🕊️🏯🐦🌕☔🎀📜💥 | **이미 있는 카드 아트를 두고** 이모지를 쓴다 |
| `4748~4820` 특수패 22종 `icon` | 💰🧺🐂🎯🧧🎀🧹🐦🏮🌀… | 22종 전부 이모지. 렌더 `9293`, 획득 팝업 `8755` |
| `4530~4541` `MONTHS` | 🌲🌸🏯🌿🪻🌺🍀🌕🌼🍁🍂🌧️ | 카드 폴백(`8600~8607`)은 **48장 전부 art가 있어 죽은 코드**. 다만 `flower`는 상단 월 라벨(`8790`)·준비화면(`9215`)·주막(`9400`)에서 살아 있다 |
| 버튼·헤딩 라벨 (ko/en/ja 3중) | `📖 족보표` `🔥 n고!` `🎉 목표 달성!` `☠ 런 종료` `🏆 승리!` `🔄 다시 도전` `🗑️ 버리기` `✨ 조합 힌트` `🍶 주막` | 거의 모든 제목에 이모지 접두사. 셋 다 강조면 강조가 없는 것 |

**고칠 방향**

- 족보표: 이모지 대신 해당 족보 구성 카드의 `Assets/*.webp` 썸네일(24~32px). 자산이 이미 있어 추가 비용 0.
- 특수패: 22종 이모지 → 단색 픽토그램 한 세트(선굵기·격자 통일). 당장은 이모지를 지우고
  **한자 1자 + 등급 테두리**만으로도 이모지보다 낫다(광=光, 피=皮 식).
- 버튼·헤딩: 이모지 접두사 제거. `🎉 목표 달성!` → `목표 달성`. 강조가 필요한 자리는
  **고/스톱 모달 하나**로 몰고 나머지는 활자 크기로 위계를 만든다.
- `MONTHS.flower`는 월 라벨에서 이모지 대신 해당 월 광/열끗 썸네일 또는 한자(`hanjaMonth`)만 남긴다.
- 카드 폴백 경로(`8600~8607`)는 죽은 코드 — 지우거나, 남긴다면 이모지 대신 텍스트 폴백으로.

## 2. Tailwind 기본 팔레트 하드코딩 171회

화투 팔레트(펠트 초록 `#1a4a2e` · 금 `#d4af37` · 주 `#c0392b`)를 정해놓고,
정작 본문·보조 텍스트·상태색은 Tailwind 기본값을 그대로 박아 넣었다.

```
#94a3b8 ×37   #e2e8f0 ×30   #cbd5e1 ×15   #f8fafc ×13   #0f172a ×11
#fecaca ×11   #fbbf24 ×10   #64748b ×10   #f1f5f9 ×6    #f59e0b ×5   …합계 171
```

`--chip-blue: #60a5fa` / `--mult-red: #f87171`(`70`)도 Tailwind blue-400 / red-400이다.
칩·배수는 이 게임의 핵심 지표인데, 색이 "어느 프로젝트에나 있는 그 색"이라 화투 화면에서 겉돈다.

**고칠 방향** — `:root`에 중립 램프를 5단계로 정의하고(예 `--ink-1`~`--ink-5`,
펠트 초록에 약간 물든 웜 그레이) 171개 하드코딩을 토큰 참조로 치환. 새 브랜드색을 만들 필요 없이
기존 `--felt`/`--gold`에서 파생하면 된다. 치환은 기계적이라 한 번에 가능.

## 3. 등급·티어가 파스텔 무지개

| 위치 | 색 | 정체 |
|------|-----|------|
| `2183~2198` 특수패 등급 오라 | 슬레이트 / 초록 / 분홍 / 호박 | Tailwind slate-400·green-400·pink-400·amber-400 |
| `2450~2454` 족보 티어 뱃지 | `#fca5a5` `#d97706` `#93c5fd` `#86efac` `#94a3b8` | Tailwind 300단계 파스텔 무지개 |
| `832` 추천 패 뱃지 | `radial-gradient(circle at 40% 35%, #ecfccb, #a3e635)` + 글로우 | 라임색 광택 구슬 |
| `872` 버리기 뱃지 | `radial-gradient(circle at 40% 35%, #fecaca, #ef4444)` + 글로우 | 빨강 광택 구슬 |

등급이 5개라고 색을 5개 쓰면 **순위가 아니라 카테고리로 읽힌다**(초록이 분홍보다 높다는 근거가 없다).
`circle at 40% 35%` 광택 그라디언트는 2010년대 웹 기본값 그대로다.

**고칠 방향** — 등급은 **금색 하나의 농도/테두리 굵기**로 표현(커먼=테두리 없음 → 레전더리=금 2px + 은은한 글로우).
족보 티어도 같은 축으로. 추천/버리기 뱃지는 광택 구슬 대신 평면 원 + 기존 `--gold`/`--red`.

## 4. 춘향 = 손코딩 SVG + 이모지 얼굴

`4375~4392`. 몸통은 `<path>`/`<circle>`로 짠 벡터인데
얼굴만 `<div id="ch-face">😴</div>`(`4392`)로 이모지를 얹었다(표정 전환 `8679~8697`, 대사 `8367~8437`).
결과적으로 **눈·입 없이 볼터치 원 두 개(`4389~4390`)만 있는 도형 위에 OS 이모지가 떠 있는** 형태.

CLAUDE.md가 "표정/대사 있는 인터랙션"을 명시한 만큼 **캐릭터 자체는 유지**한다. 문제는 구현 방식이다.

**고칠 방향** — 표정 5~7종(😴😊🤩😰🤔…에 대응)을 카드 아트와 같은 화풍으로 그려
`Assets/Chunhyang/face-*.webp`로 교체. 손코딩 SVG 몸통도 같이 그린 일러스트 한 장으로 바꾸면
카드 아트와 화풍이 붙는다. 이 항목만 유일하게 외부 아트 작업이 필요하다.

## 5. 본문 `<b>` 남발 — 240회, 한 문장에 7개까지

```
helpRoundBody: '내기 <b>4회</b> · 버리기 <b>4회</b> · 손패 <b>8장</b>. … <b>고</b> 또는 <b>스톱</b> …'   ← 7개 (5227)
coachScoredBody: '방금 <b>…</b>으로 <b>+…점</b>! 점수 = (<b>족보 칩 …</b> × <b>…배</b>) …'              ← 6개 (5303)
```

`<b>` 4개 이상인 문장이 **12개**(ko/en/ja 각각). 전부 굵으면 아무것도 굵지 않다.
카피 자체는 좋다 — 구체적인 숫자를 쓰고, "단순한 X가 아니라 Y" 류의 AI 문투가 없다. 문제는 강조 밀도뿐.

**고칠 방향** — 문장당 `<b>` 1개 상한. 숫자는 굵게 하지 말고 `--font-num`의 탭 정렬 숫자에 맡긴다.
용어(고/스톱/내기)는 첫 등장 1회만.

## 6. 유리질·과대 그림자 (부분 슬롭)

- **무의미한 blur** — `3600` 모바일 상단바가 `background: rgba(10, 28, 18, .96)`(96% 불투명) 위에
  `backdrop-filter: blur(8px)`. 시각 효과는 0이고 모바일에서 합성 레이어 비용만 낸다. → **삭제**.
  `1227`의 `blur(2px)`도 사실상 안 보인다.
- **살아 있는 blur** — `392~393`(설정 오버레이, .64 불투명)는 실제로 보인다. → 유지.
- **과대 그림자** — `0 24px 64px`(`412`), `0 18px 60px`(`1275`), `0 22px 70px`(`1513`), `0 22px 64px`(`1702`·`3907`).
  어두운 펠트 배경에서 60~70px 블러는 그림자가 아니라 화면 전체를 뿌옇게 만든다.
  → `0 12px 28px rgba(0,0,0,.5)` 수준으로. 금색 테두리가 이미 모달을 띄워주고 있다.

## 7. `01 ·`~`08 ·` 번호 키커 9개

```
<p class="eyebrow">Official game guide</p>   ← 205, 한국어 페이지에 영문 키커
<p class="eyebrow">01 · 기본 규칙</p>         ← 228,  h2는 "처음 시작하기"
<p class="eyebrow">02 · 점수</p>              ← 240,  h2는 "칩과 배수 계산법"
… 08까지 + "운영 정보"(347)
```

모든 섹션 위에 대문자 자간 넓힌 금색 키커를 얹고 `01 · 02 · 03`으로 번호를 매기는 건
2023년 이후 AI 랜딩 페이지의 가장 흔한 서명이다. 게다가 키커 내용이 h2를 다시 말하거나
(`01 · 기본 규칙` / `처음 시작하기`) 목차에 이미 있는 순서를 반복한다.
`Official game guide`는 한국어 페이지에서 아무 정보도 주지 않는다.

**고칠 방향** — `.eyebrow` 9개 전부 삭제. 순서는 이미 목차(`213~225`)가 알려준다.
h2만 남기면 위계가 오히려 선명해진다.

## 8. 본편과 폰트·색·모양을 공유하지 않는다

| | 본편 | 가이드 |
|---|------|--------|
| 제목 폰트 | `SSRock`(커스텀) | `Georgia, "Nanum Myeongjo", serif` (`97`·`58`) |
| 배경 | `Assets/Background.webp` 펠트 사진 | 붉은/금색 radial 얼룩 2개 (`35~36`) |
| 라운드 | 6~16px | 24px / 20px / 999px (`103`·`108`·`73`) |
| 버튼 | 금 테두리 사각 | 금 그라디언트 알약 (`73~78`) |

Georgia는 **한글 글리프가 없다.** 한국어 제목은 `Nanum Myeongjo`로 넘어가는데 이 폰트를
설치·로드하지 않으므로 대부분의 사용자에게는 시스템 기본 고딕으로 떨어진다.
즉 의도한 세리프는 라틴 문자에만 걸리고, 한글 제목은 아무 스타일도 받지 못한다.

**고칠 방향** — 본편의 `--font-overlay`/`--font-ui`와 팔레트를 그대로 가져온다.
`SSRock`을 웹폰트로 로드하기 부담되면 최소한 배경·라운드·버튼 모양만이라도 맞춘다.
붉은/금색 radial 얼룩은 지우고 본편과 같은 펠트 배경으로.

## 9. 전부 카드 — 카드 안의 카드

`section`(테두리 + 라운드 20px + 그라디언트 배경, `106~111`) 안에
또 `.step`/`.info-card`(테두리 + 라운드 14px, `126~131`)를 3열로 깐다. 5개 섹션이 같은 3열 카드 격자다.

- `01` 3열 스텝, `02` 3열, `04` 3열, `05` 3열, `07` 6장 — **모든 내용이 같은 무게로 보인다**
- `.formula`(`145~154`)는 왼쪽 4px 금색 바 + 등폭 글꼴. 점수 공식은 코드가 아니다 — 등폭은 의상일 뿐
- `.hero-art`: 라운드 24px + `0 26px 70px` 그림자 (`103~104`)

**고칠 방향** — 카드 격자는 진짜 병렬 항목(`07 초보 공략` 6장) 한 곳만 남기고
나머지는 본문 문단이나 정의 목록으로. `section`의 테두리·배경을 없애면 카드-속-카드가 자연히 해소된다.
`.formula`는 등폭 대신 본문 폰트 + 큰 크기, 왼쪽 바 제거.

## 스캐너 오탐 (도구 한계 메모)

문자열 매칭이라 다음은 전부 오탐이었다. 재실행 시 무시할 것.

- `17 left-border callout` → `-webkit-touch-callout: none` (`index.html:98`)
- `18 pastel icon tiles` → 춘향 SVG의 `aria-label` (`4375`)
- `09 decorative strikes` → `text-decoration: underline` — 링크 밑줄은 이 스킬이 **권장하는** 형태
- `34 tasteful-terminal` → `design/` 와이어프레임의 `var(--mono)`
- `15 emoji everywhere` 초과분 대부분 → `design/`·`docs/` 마크다운 표의 ✅
- `24 AI-drawn SVG icon` → 춘향 SVG. 지적 자체는 맞지만 "아이콘"이 아니라 캐릭터다
- `11 full-sentence display headline` → 음수 `letter-spacing`과 큰 `font-size`를 헤드라인으로 오인

또한 **한국어 카피 규칙이 없다**(스킬은 러시아어 예제 `rules.ru.mjs`만 제공).
`scripts/rules.ko.mjs`를 만들면 물결표·느낌표 남발, `<b>` 밀도 같은 항목을 자동 검출할 수 있다.

**재실행**

```bash
node .agents/skills/kill-ai-slop/scripts/scan.mjs . --exclude=design --exclude=docs
```

스킬은 `npx skills add yetone/kill-ai-slop`로 설치하며, 설치물(`.agents/`·`.claude/`·`skills-lock.json`)은
프로젝트 의존성이 아니므로 gitignore 처리했다.
