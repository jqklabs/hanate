| 항목 | 결정 |
|---|---|
| **페이월 (기능 잠금·사용량 제한·부활 판매)** | **만들지 않는다.** 수익화 방안 §2-C/D에서 기각됨 |
| 대신 만드는 것 | **전환 서피스 3종** — 정산 앵커 · 3월 돌파 토스트 · 완주 화면 |
| 1순위 요청 | **Steam 위시리스트** (무료 행동 = 마찰 최저, 수익화 §6의 유일한 선행지표) |

**핵심 원리**: 이 게임에는 잠글 것이 없다. 잠글 게 없으면 **"놓치는 것"이 아니라 "증명한 것"을 파는 수밖에 없다.** 그래서 모든 서피스의 트리거는 실패가 아니라 **성취 직후**다.

## 1. 왜 페이월이 아닌가 (설계 전제)

| 표준 페이월 트리거 | 화투로에 적용하면 | 판정 |
|---|---|---|
| 기능 잠금 | 잠글 유료 기능이 웹판에 없다. 만들면 마찰 0 유입이 죽는다 | ❌ |
| 사용량 제한 (하루 N판) | 재도전 루프 = 로그라이크의 리텐션 축 자체. 이걸 막는 건 상품을 부수는 것 | ❌ |
| 트라이얼 만료 | 계정·서버가 없다(localStorage만). 만료를 강제할 수단이 없고, 만들면 §2-D 인프라 함정 | ❌ |
| 고박 후 부활권 판매 | 고박이 런 종료라서 고가 무섭다. 되돌리는 순간 밸런스 철학 붕괴 + **현금으로 판을 되돌린다 = 사행성 오해 직격** ([사행성-비해당-사전작업.md](사행성-비해당-사전작업.md)) | ❌❌ |
| 상점 리롤 판매 | 리롤이 유한해서 상점이 선택이 된다. 동일 이유로 붕괴 | ❌ |

> **냥의 현금 구매·환전은 어떤 형태로도 도입하지 않는다.** 수익화 §4의 레드라인이며, 넘는 순간 웹보드게임 규제 범주로 이동한다.

## 2. 아하 모먼트 — 언제 물을 것인가

텔레메트리와 밸런스 실측에서 나온 지점들:

| 순간 | 근거 | 지불 의사 |
|---|---|---|
| 첫 대형 점수 폭발 | 캠페인 영상이 파는 순간 그 자체 | 중 — 아직 게임을 다 못 봄 |
| **3월 벽 돌파** | 그리디 봇 300런 중 ~86%가 여기서 죽는다 (README 밸런스) | **높음 — 실력을 증명한 첫 순간** |
| 6월 벽 돌파 | 상점 봇도 6~7월에서 전멸 | 높음 (3월과 중복 → 하나만 쓴다) |
| **12월 완주(승리)** | 목표 승률 1~5%. 가장 희소한 성취 | **최고** |
| 런 중단 (자리 이탈) | 저장이 없어 진행이 증발 — Steam판의 실질 차별점 | 중 — 상시 앵커로만 |
| 고박(패배) | 좌절 직후 | **0 — 여기서 절대 묻지 않는다** |

## 3. 서피스 3종

### S1 · 정산 화면 하단 앵커 (상시 · 비침습)

**위치**: `screen: settle` 정산 패널 하단, 다음 달 진행 버튼 **아래**. 클릭 흐름을 가로막지 않는 자리.
**노출 조건**: 런을 1회 이상 끝낸 적이 있는 유저에게만(첫 런 중에는 숨김 — 가치 경험 전).

```
────────────────────────────────
 한 판 남기고 자리를 떠야 할 때가 있다.
 이어서 할 수 있는 버전은 Steam에서 준비 중.

 [ 위시리스트에 담기 ]     [ 다음 달로 ]
────────────────────────────────
```

**왜 이 문구인가** — Steam판이 파는 건 "더 많은 콘텐츠"가 아니라 **저장**이다(수익화 §3 Phase 1). 웹판에서 유저가 실제로 겪는 결핍을 그대로 말하는 것이 가장 정직하고, 무료판을 깎아내리지 않는다. "준비 중"은 사실이며 기대를 만든다.

**대안 A** — `이 판을 저장할 수 있다면. → Steam 위시리스트` (짧게, 앵커 1줄만)
**대안 B** — `12판을 나눠서 하고 싶다면, Steam판을 기다려주세요.` (부드럽게, 도발 없음)

---

### S2 · 3월 돌파 토스트 (평생 1회 · 논블로킹)

**트리거**: 3월 정산을 통과한 직후. **유저당 평생 1회.**
**형태**: 화면을 덮지 않는 토스트. 8초 후 자동 소멸. 클릭하지 않아도 게임은 그대로 진행.

```
  🎴  3월을 넘겼습니다.
      AI 봇 300판 중 260판이 여기서 죽었습니다.

      [ Steam 위시리스트 ]   [ 계속 ]
```

**왜 이 문구인가** — 유저를 칭찬하는 게 아니라 **숫자로 증명**한다. 광고 카피에서 가장 강한 한 줄로 판정된 "그리디 AI 봇 승률 0%"와 같은 근거([copy-v3.md](../design/15_google_campaign/copy-v3.md))를 게임 안에서 회수하는 구조 — 광고를 보고 들어온 유저에게는 약속의 이행으로 읽힌다.

> ⚠️ **수치 검증 필수.** "300판 중 260판"은 README의 "3월 벽 ~14% 생존"에서 역산한 값이다. 밸런스가 바뀌면 `node test/test-game.mjs` 재측정 후 문구를 갱신할 것. **한정어 "AI 봇"을 절대 떼지 말 것** — 떼면 근거 없는 주장이 된다.

**대안** — `3월을 넘긴 사람은 드뭅니다. 12월까지 가면, 그건 기록입니다.` (숫자 없이, 검증 부담 0)

---

### S3 · 완주 화면 (승리 · 전면)

**트리거**: 12월 완주. 승리 연출이 **끝난 뒤** 별도 카드로 등장 — 승리의 순간 자체를 요청으로 덮지 않는다.

```
        열두 달을 전부 넘겼습니다.

    당신은 AI 봇이 한 번도 도달하지 못한 곳에 있습니다.

  ──────────────────────────────────────
   이 게임을 계속 만들 수 있게 도와주세요

   [ itch.io에서 응원하기 (원하는 만큼) ]
   [ Steam 위시리스트에 담기 ]

   [ 다시 한 판 ]
  ──────────────────────────────────────
```

**왜 이 순서인가** — 완주자는 이 게임의 상위 1~5%다. 지불 의사가 가장 높은 유일한 집단이므로 **여기서만 돈을 직접 요청**한다. 그래도 `다시 한 판`을 맨 아래 남겨 거절 경로를 항상 열어둔다.

**PWYW를 쓰는 이유** — 가격을 제시하면 "이 정도 값어치인가"를 판정당한다. 완주 직후에는 **금액이 아니라 감정이 결정**한다.

---

### S4 · 고박 화면 — **서피스 0개** (규칙)

```
        고박.  (다시 하기)
```

패배 화면에는 위시리스트도, 후원도, 링크도 넣지 않는다.

- 좌절 직후의 요청은 신뢰를 깎고, 이 게임의 리텐션은 **즉시 재도전**에서 나온다.
- "실패했으니 돈을 내라"는 구조는 사행성 오해의 정확한 형태다. 문서로 비해당을 입증하는 중에 스스로 근거를 만들 이유가 없다.

## 4. 빈도 · 상태 관리 (localStorage 전용)

계정이 없으므로 전부 로컬 상태다. 브라우저를 지우면 초기화되는 것을 감수한다(요청은 서피스일 뿐, 자산이 아님).

```js
// hwatro_conv
{
  runsFinished: 3,          // S1 게이트 (>=1)
  s2Shown: true,            // S2 평생 1회
  s3DismissedAt: 1760000000000,
  clickedOutAt: 1760000000000  // 위시리스트/itch로 나간 시각
}
```

| 규칙 | 값 |
|---|---|
| S1 노출 | `runsFinished >= 1` 이후 상시 |
| S2 노출 | 평생 1회 (`s2Shown`) |
| S3 노출 | 완주할 때마다. 단 닫은 뒤 **30일 쿨다운** |
| **전환 후 침묵** | 어떤 서피스든 클릭해 외부로 나가면 **90일간 전 서피스 숨김.** 이미 응답한 사람에게 다시 묻지 않는다 |
| 세션당 상한 | 전면 서피스(S3)는 세션당 1회 |

## 5. 계측 (기존 GA4에 이벤트 3개 추가)

`firebase-telemetry.mjs`에 붙인다. 기존 이벤트 스키마와 동일한 방식.

| 이벤트 | 파라미터 |
|---|---|
| `conv_impression` | `surface`(s1\|s2\|s3), `month`, `runs_finished` |
| `conv_click` | `surface`, `target`(steam\|itch), `month`, `runs_finished` |
| `conv_dismiss` | `surface`, `month` |

**읽을 값**

| 지표 | 산출 | 의미 |
|---|---|---|
| 서피스별 CTR | `conv_click` / `conv_impression` | 어느 순간이 실제 전환 순간인지 |
| S2 CTR vs S3 CTR | — | 성취의 크기와 지불 의사가 비례하는지 검증 |
| itch 전환율 | 결제 / 웹 유니크 | 수익화 §6 게이트 **≥ 0.5%** — Phase 1 착수 판단의 핵심 |
| 위시리스트 증가 | Steamworks | 출시 전 7,000 목표 (§6) |

## 6. 테스트 우선순위

| # | 테스트 | 가설 |
|---|---|---|
| 1 | **S2 문구**: 숫자 도발(`봇 260판이 죽었다`) vs 편익(`저장되는 버전`) | 성취 직후엔 자부심 자극이 편익 설명을 이긴다 |
| 2 | **S3 순서**: itch 먼저 vs 위시리스트 먼저 | 완주자에겐 돈 요청을 앞에 둬도 이탈하지 않는다 |
| 3 | **S1 게이트**: `runsFinished >= 1` vs `>= 3` | 너무 이른 요청은 CTR과 리텐션을 동시에 깎는다 |
| 4 | **S2 트리거**: 3월 vs 6월 | 벽이 높을수록 성취감이 크지만 모수가 준다 |

트래픽이 얇으므로 동시에 하나만. 최소 2주 또는 서피스당 노출 500회 중 늦은 쪽까지 돌린다.
