# 화투로 — 추가 시스템 구현 계획

> 기준 기획: [추가시스템-기획.md](추가시스템-기획.md)
> 코드 기준: `index.html` 단일 파일 · `==== ENGINE START/END ====` 순수성 유지
> 테스트: 엔진 수정마다 `node test/test-game.mjs`

이 문서는 **구현 순서와 침투 지점**만 담는다. 효과 수치·카탈로그는 기획서를 따른다.

---

## 0. 불변 조건

- 엔진 마커 안: DOM·경제 지급 금지. 순수 계산·명령 반환만.
- 족보·core는 `detectHandInfo` 한 곳에서만 결정.
- `Math.floor`는 최종 점수에서 1회만.
- 선택은 `uid`, 영구 강화·소각·생성은 `cardKey`.
- 경제·성장·RNG 소비는 확정 행동에서만. 프리뷰는 드라이런.
- 고 선언은 `goLevel` 확정 → `onGo` 1회 → 손패 보충. 밀치기여도 `onGo`는 1회.
- 밸런스: 무특수패·무강화 런의 3월 벽을 깨지 않는다. 하향보다 상향 우선.

---

## 1. 권장 구현 순서

특수패 40종을 먼저 넣지 않는다. 패단장·덱 변형에 의존하는 카드가 많으므로
**골격 → 훅 → 패단장 → 특수패 → 춘향** 순으로 간다.

| 단계 | 목표 | 완료 기준 |
| --- | --- | --- |
| **A** | `cardKey` / `runDeck` 골격 | 강화 없이 기존 48장·점수·봇 결과 동일 |
| **B** | `resolveSpecialCards` 훅 엔진 | 현행 22종을 훅으로 이식, 수치·동작 동일 |
| **C** | 점괘·패단장 MVP | 상점 점괘 2개 + 8장 선택 + 8종 단장 |
| **D** | 특수패 40종 교체 | 커먼→레어→에픽→전설, 검증용 6종부터 |
| **E** | 춘향의 밑장 | 3·6·9월 박 뒤 3택 1, 레거시 훈수 제거 |
| **F** | 확장·캘리브 | 비책 10종, 봇·600런 재검증 |

## 2. 단계별 상세

### A. 런 덱 골격 (효과 없음)

**목적**: 매 판 `shuffle(buildDeck())`를 영구 덱 모델로 바꾸되 점수는 그대로.

1. `buildDeck()`에 기본 48장 `cardKey` 부여 (`m03-pi-1`, `m08-godori` 등).
2. `state.runDeck` 추가:
   ```text
   removedCardKeys[]
   generatedCards[]
   cardMods{}
   cardTransforms{}
   jadeDustByMonth{}
   ```
3. `materializeRunDeck(runDeck)` → 기본+생성−소각 → `uid` 재부여 → shuffle.
4. `startRound()`의 `shuffle(buildDeck(), rng)`를 `materializeRunDeck`으로 교체.
5. `resetRun()`에 `runDeck` 초기화. (money·jokers·stats는 기존 유지 규칙 그대로)

**테스트**: 기존 전 스위트 통과. 시드 고정 한 판의 점수·드로우 순서 회귀.

**건드리는 곳**: `buildDeck`, `startRound`, `resetRun`, `state`.

---

### B. 공통 훅 엔진

**목적**: `addChips/addMult/xMult`와 `hasJoker()` 산재를 한 경로로 모은다.

#### B.1 엔진(순수)

`ENGINE END` 직전에:

```text
resolveSpecialCards(event, snapshot)
  → { scoreMods, commands[], triggers[], pendingReward }

applyScoreModifiers(base, scoreMods)
  → chips / +mult / ×mult 합산 (기존 순서 유지)

pickAutoTarget(rule, cards|jokers)
  → 최저 칩 → cardKey → uid 순 동률 해소
```

이벤트 목록:

| event | 호출 시점 |
| --- | --- |
| `roundStart` | `startRound` 배분 직전·직후 |
| `beforeScore` | `detectHandInfo` 전 (감춤·가상 월) |
| `cardScored` / `held` / `score` | `computeScore` 안 |
| `afterScore` | `playSelected` 점수 확정 뒤 |
| `discard` | `discardSelected` 확정 시 |
| `go` / `stop` | `chooseGo` / `chooseStop` |
| `bossLoss` | 박으로 칩이 실제로 0이 된 뒤 |
| `shop` / `reroll` / `buy` / `sell` | 상점 행동 |
| `enhance` / `destroy` | 단장·소각 확정 뒤 |
| `jokerTrigger` / `jokerDestroy` | 다른 특수패 발동·파괴 뒤 |

공통 명령: `gain`, `grow`, `decay`, `charge`, `release`, `setTarget`,
`moveCard`, `maskCard`, `enhanceCard`, `transformCard`, `duplicateCard`,
`destroyJoker`, `destroySelf`, `evolveJoker`, `copyAbility`.

`synthetic` 표식 명령은 `onEnhance` / `onDestroy` / `onJokerTrigger`를 재발동하지 않는다.

#### B.2 UI(엔진 밖)

```text
applyJokerCommands(commands, { dryRun })
```

- 프리뷰: `dryRun: true` → 배지만, 상태·냥·RNG 미소비.
- 확정: 명령 1회 적용 + 짧은 연출.

#### B.3 현행 22종 이식

효과·가격·희귀도는 그대로 두고 훅 경로만 바꾼다.

| 현행 처리 | 이식 후 |
| --- | --- |
| `computeScore`의 addChips/addMult/xMult | `score` 이벤트 scoreMods |
| `playSelected` 광팔이 | `afterScore` → `pendingReward` |
| `discardSelected` 밑장빼기 누적 | `discard` → `grow` (임시, D단계에서 교체) |
| `cardChip` 피박보험 | `cardChip` 또는 `bossLoss` 억제 |
| `settle` 피박보험 +1냥 | `stop`/`roundEnd` pendingReward |

**테스트**: 기존 특수패 단위 테스트·시뮬레이션 assert 전부 통과.

### C. 점괘·패단장 MVP

1. 상점 `genOffers`에 점괘 2슬롯 병행 (`shopHTML` 섹션 분리).
2. `buyFortune(i)` → 후보 8장 한 번만 확정 → 선택 모달.
3. `applyEnhancement(cardKeys, enhancementId)` → `cardMods`.
4. `cardChip` 순서: 기본 → 이달×2 → 밤낮+2 → 금박/복문 길 → 박 0.
5. `detectHandInfo`에 도깨비무늬(본래/진행 월)·장승패(병풍 빈 월) 전처리.
6. `computeScore`에 홍칠·옥장·무쇠장·복문 대길·장승 flat.
7. 확정 후: 옥장 파손·옥가루, 엽전 충전, 고/스톱 엽전 정산.
8. `cardHTML` / `deckpeekHTML`에 단장 테두리·운세 배지.

**MVP 우선 단장**: 금박 → 홍칠 → 나머지 6종.

**테스트**: 단장 순서·덮어쓰기·다음 월 유지·프리뷰 RNG 불변.

---

### D. 특수패 40종 교체

1. `JOKERS` → 기획 40종 `SPECIAL_DEFS`로 교체. **같은 id라도 효과가 바뀐 카드는 테스트 일괄 갱신**.
2. `state.jokers`: `{ id, paid, data }`. `mitjangChips`·`kwangSoldThisRound` 등 전역을 `data`로 이동.
3. 보유 칸에 현재값·다음 목표 표시.
4. 검증용 6종을 먼저 완성한다:
   - 장독대 (charge/release)
   - 복주머니 (go/stop 분기)
   - 금줄 (bossLoss)
   - 도깨비방망이 (enhanceCard)
   - 작두 (destroyJoker)
   - 팔도유람 (evolveJoker)
5. 그다음 커먼 16 → 레어 13 → 에픽 8 → 전설 3.
6. 상점 봇이 충전·고 분기·단장을 이해하도록 갱신 후 300런.

**동일 id 주의** (효과 전면 교체):

| id | 구 효과 | 신 효과 |
| --- | --- | --- |
| `mitjang` | 버리기마다 +10 누적 | 첫 버리기 최저칩 귀환 |
| `jjokjipge` | 쪽이면 +2배수 | 매 판 예언 족보 |
| `bigwang_usan` | 비 core ×2 | 박 손실 → 다음 일반 판 방출 |

---

### E. 춘향의 밑장

1. `CHUNHYANG_ENABLED` 훈수·예약·호버 예측 경로 제거 (또는 영구 dead code 정리).
2. `screen: 'chunhyangReward'` 추가.
3. 3·6·9월 박 `settle` 뒤 → 밑장 3택 1 → `openShop`.
4. 12월은 보상 없이 승리 결산.
5. MVP 6종: 귀물부림, 광명부, 환골탈태, 혼례상, 살풀이, 업보장부.
6. `offeredIds`로 런 내 중복 방지. 대상 불가 비책은 제안에서 제외.

---

### F. 확장·캘리브레이션

- 비책 10종 전체.
- 12월 마지막 밑장(결산 분류) 검토.
- 봇·사람 로그로 가격·목표 조정.
- 최종 600런: 3월 벽·6~7월 도달률·냥 잔액·12월 승률.

## 4. 위험과 대응

1. **프리뷰가 상태를 소비** → resolve는 순수, apply는 확정 1회.
2. **족보와 core 분리** → 단장·감투 전처리도 `detectHandInfo` 경로 안.
3. **uid / cardKey 혼동** → `materializeRunDeck`에서만 uid 재할당.
4. **같은 id·다른 효과** → 테스트·봇·도움말 동시 갱신.
5. **봇이 고/충전을 모름** → 단계 D부터 봇 재작성 없으면 밸런스 수치 무효.
